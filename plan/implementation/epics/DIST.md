# Epics: Distributed runtime
- RFCs: RFC-0030, RFC-0031, RFC-0032, RFC-0033, RFC-0034   ADRs: ADR-0300–ADR-0316; foundational ADR-0000 (D3, D4), ADR-0006, ADR-0008 (item 6), ADR-0009, ADR-0010, ADR-0011, ADR-0012, ADR-0013 (history spill), ADR-0014, ADR-0015, ADR-0016, ADR-0017, ADR-0019, ADR-0020

Conventions:
- A "§" reference in a task points to the RFC named in that task's Implements column.
- Milestones follow RFC-0001 §16 (M0–M4).
- Every number in an acceptance criterion is either a target from `00-vision-and-scope.md` §7 (cited as SC-n) or a figure from the cited RFC's own design or performance section.
- "Simulator" means the deterministic multi-node simulator of RFC-0060 (QUAL-E8). "Rig" means the reference hardware of RFC-0061 (QUAL-E15).
- Cross-area dependencies cite the other area's epic or task ID where it is known. Otherwise they name the item, for the integrator to resolve.
- Epic DIST-E1 covers the daemon–runner process model (RFC-0001 §3, ADR-0015). Other areas' epics already cite it as "DIST/PROD", and the integrator may move it.

## Epic DIST-E1: Process model: rings, IPC, runner spawn, lifecycle and supervision
- **Goal.** The daemon spawns, supervises and talks to per-instance runner processes exactly as RFC-0001 §3 specifies. The daemon never opens a GPU context. A runner crash never takes the daemon down.
- **RFC sections implemented:** RFC-0001 §3.1–§3.5 and §8.3; RFC-0033 §8.2 (supervision defaults); RFC-0034 §6.4 (IPC peer checks)
- **ADRs implemented:** ADR-0015, ADR-0012 (rings and signalling)
- **Crates touched:** `ipc`, `core`, `daemon`, `runner`, `cli`, `testkit`
