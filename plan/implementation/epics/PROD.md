Conventions:
- Milestones are RFC-0001 §16's.
- SC numbers refer to `00-vision-and-scope.md` §7.
- "Fake runner" means `syntropy-testkit`'s runner stand-in (QUAL-E3-T12, QUAL-E8-T06), which lets API, CLI and dashboard work run without GPUs.
- Cross-area dependencies cite task IDs where the other area's epic exists. Otherwise they name the work in a `TBD:` segment until that task exists.

## Epic PROD-E1: Configuration and policy
- **Goal:** one optional TOML file per node and one generated schema; the four RFC-0001 scopes with the cluster layer in the event log; the policy objects every area consumes; validation, writes and reload that never fail a sequence; the gated debug keys the quality area needs from M0.
- **RFC sections implemented:** RFC-0054 §1–§10.
- **ADRs implemented:** ADR-0500, ADR-0501, ADR-0019 §6–§7, ADR-0000 D3 and D4, ADR-0007 (budget policy), ADR-0008 decision 8, ADR-0009 decision 7.
- **Crates touched:** `config`, `core` (policy objects), `daemon` (reload, proposals), `ipc` (`ConfigChanged`), `cli` (`config` commands).

## Epic PROD-E5: API authentication, bind policy and LAN TLS
- **Goal:** chat and read-only calls on loopback work with no keys and are protected against browsers, while administrative, session and keyholder actions need the local socket or a key. Every other bind needs a key and TLS, and the per-node local CA, narrowly constrained, makes LAN TLS practical. Overlay binds may omit TLS. Plain HTTP on a LAN is an explicit, permanently flagged opt-in. The prefix cache never leaks across principals.
- **RFC sections implemented:** RFC-0050 §11 (§11.1, §11.1.1, §11.2–§11.5), §9.5.
- **ADRs implemented:** ADR-0505; RFC-0001 §12 zone Z3; RFC-0034 R1–R5.
- **Crates touched:** `api`, `daemon`, `cli` (`api-key`, `trust`), `core` (key and CA types).
