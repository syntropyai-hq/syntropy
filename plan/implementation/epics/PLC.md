Conventions: "§" references are to the RFC named in the task. Milestones follow RFC-0001 §16 (M0–M4). Benchmarks run on the reference rigs RFC-0061 names; every number in an acceptance criterion is a target from `00-vision-and-scope.md` §7 (cited as SC-n) or from the RFC's own performance table.

## Epic PLC-E1: Resource graph types and hardware enumeration
- Goal: every device, tier and link the solver may use is enumerated on every supported OS without external tools or privileges, deduplicated across providers, and assembled into a `ResourceGraph`.
- RFC sections implemented: RFC-0010 §1 (1.1–1.4), §2 (2.1–2.2), §8, §9 (enumeration rows)
- ADRs implemented: ADR-0014 (rule 1, unified-memory capacity rules), ADR-0015 (probe-mode runner), ADR-0020 (platform tiers), ADR-0009 (graph via the event log)
- Crates touched: `core`, `probe`, `daemon`, `runner`, `kernels` (types), `net` (E4), `cluster` (assembly)

## Epic PLC-E2: Startup microbenchmark suite
- Goal: every first-order cost-model input is measured with the real kernel and request size, within 15 s per node, with the slow measurements (sustained NVMe, device-path α_eff, model-specific schemes) run in the background or on demand.
- RFC sections implemented: RFC-0010 §3 (3.1–3.5, including H5 lock accounting and the RFC-0021 §10 engine selection in S1), §4, §9 (probe failure rows)
- ADRs implemented: ADR-0100, ADR-0006 (item 2 gate measurement), ADR-0011 (per-transport link measurement), ADR-0013 (probing through the real I/O engines), ADR-0014 (rule 3 measurement), ADR-0012 (CPU measured with reserved cores excluded)
- Crates touched: `probe`, `runner` (probe mode), `kernels`, `io`, `net`, `daemon`
