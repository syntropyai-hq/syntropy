Conventions: "§" references in the Implements column are to the RFC named beside them. Milestones follow RFC-0001 §16 (M0–M4). Benchmarks run on the reference rigs RFC-0061 names (R-ADA, R-BW, R-WIN, R-MACF, R-ULTRA, R-LABCPU, R-DUAL, R-AMD, R-ARC, R-GB10 and the multi-node pairs). Every number in an acceptance criterion is a target from `00-vision-and-scope.md` §7 (cited as SC-n) or from the named RFC's performance or testing tables; none is a measurement. Cross-area dependencies use the other areas' prefixes (PLC, TIER, DIST, PROD, QUAL); where an ID is not known yet, the dependency is named in words for the integrator.

## Epic COMP-E1: Kernel provider core
- Goal: one `KernelProvider` contract, op vocabulary, argument layout and reference semantics that every provider implements and the executor uses, with no backend code outside provider crates.
- RFC sections implemented: RFC-0040 §1, §2.1, §2.2, §2.3, §2.4, §3.1 (including the 2026-10-20 encoder and reserved ops), §3.2, §3.3, §3.4 (types and `assign`), §3.5, §5.5, §8.5 (second implementations), §12, §13
- ADRs implemented: ADR-0002 (items 2, 3, 6), ADR-0404 (items 1, 2, 4), ADR-0012, ADR-0014 (rule 4 kill switches), ADR-0001 (decision 4, unsafe policy)
- Crates touched: `kernels`, `core`, `testkit` (with QUAL)
