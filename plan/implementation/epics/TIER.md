Conventions: "§" references are to the RFC named in the task's Implements column. Milestones follow RFC-0001 §16 (M0–M4). Benchmarks run on the reference rigs RFC-0061 names. Every number in an acceptance criterion is a target from `00-vision-and-scope.md` §7 (cited as SC-n) or from the named RFC's performance or testing tables; none is a measurement. "Fake OS" and "fake provider" are the `syntropy-testkit` doubles (QUAL). Cross-area dependencies use the other areas' prefixes; where an ID is not known yet, the dependency is named in words for the integrator.

## Epic TIER-E1: Tier manager core: arenas, handles and residency
- Goal: one tier manager per runner owns every resident byte through typed arenas, 16-byte tensor handles and a single-writer residency map, with no allocation, lock or synchronising call on the token path after `Warming`.
- RFC sections implemented: RFC-0020 §1, §2, §3, §4.1 (fixed-slab row), §4.2 (`Pageable`), §4.4, §7 (7.1–7.5), §12, §13, §15
- ADRs implemented: ADR-0007 (items 1, 2, 8), ADR-0002 (all allocation through `KernelProvider`), ADR-0012 (single writer per device, SPSC commands), ADR-0015 (runner lifecycle)
- Crates touched: `tier` (new: `os`, `budget`, `arena`, `pin`, `residency`, `pressure`, `eip` modules), `core`, `runner`, `obs`

## Epic TIER-E2: Host memory: budgets, pin classes, progressive pinning and unified memory
- Goal: host RAM is used up to per-OS limits without OOM kills or desktop freezes; only bytes a device copies are DMA-registered; unified-memory machines get one `Unified` tier capped by the OS working-set limit, raised only through `syntropy tune`.
- RFC sections implemented: RFC-0020 §2 (pin classes), §4.2, §5, §6, §9, §9.1, §16
- ADRs implemented: ADR-0200, ADR-0007 (items 3, 4, macOS rule), ADR-0014 (unified-memory capacity rules, `MTLResidencySet`, pinned-arena fallback), ADR-0020, ADR-0000 D1
- Crates touched: `core` (budget rule), `tier` (`os`, `budget`, `pin`, `arena`), `probe`, `runner`, `cli` (with PROD)
